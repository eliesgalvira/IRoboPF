# Corroboración técnica condicionada de escalas, bases y mínimos

La revisión independiente y el contraste de sus resultados corroboran los 28 sitios de escalas, bases y mínimos bajo las condiciones descritas. No se reproduce un defecto funcional nuevo.

## Qué se corrobora

Los 22 sitios generales conservan las relaciones entre entradas, productores, selección de tablas, invocaciones, valores y líneas de cálculo dentro del dominio ordinario, acíclico, finito y síncrono fijado. Los seis explícitos cubren Madrid 2025, trabajo o pensión. Sus variantes de actividad tienen un bloqueo concreto: consumen `aporte.importeEurosExactos`, producido por el adaptador y las 19 familias excluidas. La API financiera real admite el caso, la sensibilidad de esa propiedad altera las seis salidas y el modo causal rechaza al llegar al productor excluido.

No se equiparan estas conclusiones con validación fiscal ni con una liquidación completa. Los derechos y hechos familiares deben estar previamente admitidos; el marcador rightsPreadmitted no los acredita. El servicio normativo es el concreto de las fuentes verificadas, no cualquier capa inyectada. El decoder actual preserva estructuralmente las entradas aceptadas: la reutilización del raw input no se declara una implementación genérica de defaults o transformaciones futuras. La equivalencia universal de Effect y R40-03 siguen fuera.

El dictamen individual está en `../../revisiones/causal-escalas-r62-sol/DICTAMEN28.json`. Expone objeción, respuesta, coste y alcance para cada ID. La muestra por sí sola no demuestra todo el dominio: el respaldo es conjunto de lectura de fuente, relaciones por propiedad, API real, cálculo racional y contrapruebas. El replay comparte semántica y no se presenta como oracle independiente.

Las 28 anclas de importe coinciden con los archivos reales por SHA256 y posición UTF16. La matriz tiene exactamente 28 IDs y distingue las seis variantes bloqueadas. Los 36 casos contienen 792 salidas; estos recuentos se solapan con las comprobaciones siguientes y no se suman como reglas fiscales.

El contraste de integración reproduce las 183 comparaciones racionales (153 anuales y 30 explícitas): todas correctas y ambos archivos de resultados idénticos byte a byte a los del revisor. El arnés solo cambia la ruta de sus datos hacia el scratch propio; conserva intactas fórmulas y aserciones. Se inspeccionan los ensayos de API real, relaciones, fuentes, decoder y adversos, sin atribuirlos como nuevas ejecuciones de integración.

El revisor ejecutó tres pruebas propias en dos archivos, con 36 casos/792 salidas frente a la API real, 20 rechazos o comprobaciones adversas, sensibilidad de seis variantes de actividad y cinco éxitos de decoder iguales a la entrada. Es evidencia del revisor, inspeccionada en la integración; no se atribuye como otra ejecución propia. Las 107 pruebas y tipos principal/vendor verdes de R62 se conservan como validación de los mismos bytes de producto. No se repiten sin cambios ni defectos que lo justifiquen.

## Límites e incidencias conservados

Ajv del revisor fue cancelado mientras esperaba el lock, exit 143, antes de iniciar Node: no hay pase de schema para sus 36 testigos nuevos. Sí existe la comprobación estricta anterior de 50 testigos/1.144 salidas y de su contrato, con otros bytes e identidades. No se extiende ese pase automáticamente a los 36 nuevos. El ensayo de digest documental adicional del revisor no tomó el lock pesado; no ejecutó fórmulas. Los cotejos físicos y ensayos financieros sí quedaron serializados. No se repite una revisión favorable por esas incidencias documentadas.

Se conservan los errores iniciales del arnés del revisor: carga Bun incompatible, expectativa incorrecta de una fila cero y ejecución del racional antes de existir el resultado adicional. No se atribuyen a defectos del producto ni se cuentan como pases. La recepción de R63 no altera esos logs.

CheckJs mantiene deuda visible: 43 diagnósticos en el host con noImplicitAny desactivado y 1.102 en otro host estricto no son comparables. Tipos TS verdes no certifican MJS integral. El lint de R62 acabó sin errores y con 16 avisos ESLint, cuatro del auxiliar de ensayo. No se introducen fixes ni se desactivan reglas en esta recepción documental.
