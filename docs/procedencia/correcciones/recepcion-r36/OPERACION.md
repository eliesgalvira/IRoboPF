# Incorporación local y recuperación

La operación solo afecta al checkout y sus archivos locales. No se ha desplegado ni contactado con producción. El CAS de publicación está en `/home/elies/Repos/IRoboPF/.cache/procedencia/publicacion-cas/sha256`, fuera de T3. Para ejecutar localmente las rutas/verificadores de snapshots v3 se fija `IROBOPF_CAS_LOCAL` a esa ruta absoluta. No se modifica la configuración del servicio de producción ni se establece un fallback silencioso.

`aprobacion-local.json` autoriza exactamente el plan y las identidades cotejadas en `autoridad.json`. `plan.json` contiene los bytes previos/posteriores de los dos registros. `incorporacion-local.json` fija el resultado y el diario local. El preparador permite reproducir el mismo plan desde el par previo o posterior; un par mixto debe recuperarse primero. No reescribir los informes R19 ni las atestaciones para representar la aprobación del padre.

Si una operación local se interrumpe, detener otros escritores de estos archivos. Leer y comprobar el hash del plan contra `aprobacion-local.json`; conservar el estado observado. Importar `transicion.py` y ejecutar `transition(root, plan, 'before', journal)` para restaurar ambos registros, o `'after'` para completar. Usar el mismo bloqueo `flock /tmp/irobopf-validacion-pesada.lock`. El procedimiento rechaza bytes desconocidos; en ese caso no usar reset ni sobrescribir: el cambio necesita revisión. Los ensayos de fallo tras cada escritura se conservan en `recuperacion-probada.json` y el scratch R36.

La escritura es serial. El diario y los reemplazos usan fsync, pero no se promete atomicidad dual ni comportamiento universal ante pérdida de energía. Si falla el último fsync puede haber bytes nuevos visibles; se inspeccionan por hash antes de reanudar. Un proceso lector concurrente podría ver estado intermedio. Esta receta no es un activador para un servicio en funcionamiento.

`plan-publicacion.json` conserva los extremos de `snapshots.json` y `rastro-generado.json`. Los objetos nuevos se copian y verifican antes de registrar el snapshot; el rastro se cambia después de enumerarlo. Ante interrupción, conservar objetos inmutables, comprobar esos dos extremos y restaurar primero el rastro previo si se decide volver atrás. No eliminar snapshots u objetos históricos como recuperación. El primer intento falló antes de estas escrituras; su log y su entrada se conservan.
