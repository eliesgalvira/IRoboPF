# Comandos y entorno

Documento histórico del candidato de este directorio. Los resultados y estados corresponden a esa versión; no acreditan el estado actual del proyecto.

Todos desde el checkout `t3-df42362b`, salvo la proyección de calidad expresamente indicada. Los procesos pesados adquieren `/tmp/irobopf-validacion-pesada.lock` y lo liberan al terminar cada ejecución. No se ejecuta build ni suite legacy masiva. Herramientas mediante Nix; no instalaciones globales. No se ejecuta Python ni se crea entorno Python.

- Pruebas: `nix shell nixpkgs#bun nixpkgs#nodejs nixpkgs#git -c flock /tmp/irobopf-validacion-pesada.lock bash .cache/flujo-retenciones-ss-r30/check.sh`. El script usa Vitest del integrador, un trabajador y configuración scratch con alias exactos de Effect/TypeScript, para resolver las dependencias sin escribir node_modules en la raíz. Primera ejecución con config de raíz: fallo de entorno; segunda ejecución: rojo de binding. Los intentos de desarrollo se conservan.
- Generación: `nix shell nixpkgs#nodejs nixpkgs#git -c flock /tmp/irobopf-validacion-pesada.lock node scripts/procedencia/flujo-retenciones-ss.mjs`. El primer intento conservado encontró una conversión mal etiquetada en la traza de selección; se corrigió la representación sin tocar el cálculo. Resultado actual en los logs finales.
- Contraste base/actual: `flock /tmp/irobopf-validacion-pesada.lock node .cache/flujo-retenciones-ss-r30/contraste.mjs`, dentro del shell Nix de Node y Git. Copia de base por `git cat-file`, adaptación exclusivamente de imports registrada en `adaptacion-base.json`.
- Calidad global: desde `.cache/flujo-retenciones-ss-r30/calidad`, `bun run typecheck` y `bun run lint`, cada uno con flock. package.json, tsconfig y configuraciones originales; dependencias compartidas en solo lectura. Única adaptación del script: oxlint añade `--threads=1`; conserva `--disable-nested-config` y las dieciséis reglas a error. El alcance efectivamente recorrido debe leerse en el log, sin deducir cobertura de un código cero.
- Transporte: `flock /tmp/irobopf-validacion-pesada.lock node .cache/flujo-retenciones-ss-r30/empaquetar.mjs`, dentro de Nix Node/Git/diffutils/patch. Parche textual gzip sobre blobs de base de las rutas afectadas, binarios por ruta/hash y comprobación de todos los bytes del payload. Sin commits ni mutaciones VCS.

El manifiesto excluye su propio sobre para evitar una dependencia circular de hashes. Objeción archivística: excluir controles puede ocultar omisiones. Respuesta: la lista de exclusiones es nominal y solo contiene manifiesto, parche, lista binaria y recibo de transporte; los controles físicos y de pruebas forman parte del payload. Coste: el receptor debe distinguir payload y sobre y contrastar ambos.
