## Dominio y fronteras de valor

El dominio runtime comprueba datos planos/arrays, primitivos admitidos, Date y los Decimal nativos CJS/ESM del paquete recibido. Rechaza proxies, accessors, símbolos propios, ciclos y subclases/prototipos ajenos como pending fuera del contrato, sin ejecutar sus getters. No se extrapola a JavaScript arbitrario. El consumidor está destinado a fragmentos de esta edición fijados y revisados; no se presenta como entorno aislado para programas arbitrarios. El schema familiar conserva sus límites y uniones R35. Transmisiones tiene un schema ejecutable por propiedad, variantes y unidades; fuera de ese dominio no se atribuye un rechazo al motor.

SS, netos de trabajo/alquiler/ganancias y otras fórmulas monetarias son fronteras de valor identificadas, sin recodificar fiscalidad. Sus operandos posicionales, transportes, salidas requeridas y unidades están en los contratos/instancias del JSON. Las conversiones monetarias sí ejecutan el programa puro real y declaran céntimos/EUR. Un callback suministrado o una cifra coincidente no constituye éxito: se exige resultado explícito ligado al nodo e iguales argumentos codificados de esa instancia. Las salidas requeridas se validan; ausencia no se rellena con cero. Para mínimos con derechos se reejecuta selección y se exige que atribuciones, sujetos, orden y divisores conserven esa selección.

Para el servicio anual sustituido se deriva además el DTO completo de éxito y de los dos errores declarados: propiedades anuales, Option/conciliación y rastro tienen schema ejecutable. El contraste positivo usa un recibo fijado antes de evaluar; cambiar de caso no lo reutiliza. Un objeto con solo etiqueta/motivo o unas cifras no satisface ese contrato.

El recibo permite evaluar composición con los valores de otro dominio; no autentica su emisor ni acepta la fórmula. Si falta evidencia de esa instancia, el resultado es pending, también cuando una función default tiene una salida de valor aún no aportada a la composición. Este requisito no se disfraza de rechazo del motor ni de cierre universal de implementaciones inyectadas. Los contratos del default y sus rutas están representados; las cuotas, mínimos monetarios y retención completa conservan sus fronteras de valor y revisión propias.

Los cuatro resultados tienen significado separado: success termina el programa dentro de sus contratos y evidencia aportada; reject corresponde a un fallo explícito de admisión/servicio; defect registra una excepción evaluada o incumplimiento del contrato de salida; pending significa dominio o evidencia aún no aportados. Los valores sintéticos de los ensayos de propagación solo prueban esas relaciones, no cuotas fiscales. Las APIs reales se usan para contraste independiente en las pruebas, nunca como primitiva del consumidor. El ensayo autónomo prohíbe importar motor, TypeScript y productores R32/R35.
