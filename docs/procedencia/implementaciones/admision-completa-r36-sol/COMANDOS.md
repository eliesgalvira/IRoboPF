# Comandos y resultados

Documento histórico del candidato de este directorio. Los resultados y estados corresponden a esa versión; no acreditan el estado actual del proyecto.

Dependencias utilizadas en la validación:
`IROBOPF_DEPENDENCIES_PACKAGE=/home/elies/Repos/IRoboPF/package.json`.
No Python, pip, instalaciones globales ni entornos nuevos. Node/Bun se obtienen mediante Nix.

- Rojos previos: `flock /tmp/irobopf-validacion-pesada.lock nix shell nixpkgs#nodejs -c node /home/elies/Repos/IRoboPF/node_modules/vitest/vitest.mjs run --config .cache/admision-completa-r36/vitest-r35.mjs`; salida 1, 312 casos: 301 correctos y once fallos (cinco recibidos y seis R36). Fuente y log conservados en scratch/controles.
- Históricos finales: mismo bloqueo/runtime/Vitest, `--config .cache/admision-completa-r36/vitest-historicos.mjs --reporter=default --reporter=json --outputFile=.cache/admision-completa-r36/pruebas-historicas.json`; salida 1, 306 casos: 301 correctos y los mismos cinco rojos. Se conservan todos los esperados recibidos, incluidos 204+27 y 75 R35.
- Propios: mismo bloqueo/runtime/Vitest, `--config .cache/admision-completa-r36/vitest-propios.mjs --reporter=default --reporter=json --outputFile=.cache/admision-completa-r36/pruebas-propias.json`; resultado final en VALIDACION.json y propios-terminal.log. Incluye 69 regresiones de casos JS recibidos con import del intérprete adaptado; las otras seis pruebas TS originales siguen en la suite histórica. No se suman estas repeticiones como reglas aceptadas.
- Mutaciones previas: misma configuración con `-t 'unidades y bindings'`; tres fallos, salida 1, antes del endurecimiento del verificador. Se conserva rojos-unidades-bindings.log. Otros dos rojos de dominio/DTO y uno del error completo se conservan en rojos-dominio-resultado.log y rojo-fallo-dto.log.
- Tipos/lint: bajo un flock pesado, `nix shell nixpkgs#nodejs -c bash .cache/admision-completa-r36/calidad.sh`. Ejecuta tsc `--noEmit -p .cache/admision-completa-r36/tsconfig.json` y oxlint `--threads=1 --disable-nested-config -c .cache/admision-completa-r36/oxlint.json scripts/procedencia/flujo-admision-r36*.mjs tests/flujo-admision-r36*.test.ts docs/procedencia/implementaciones/admision-completa-r36-sol/*.mjs`. Tipos iniciales 2, final 0; lint inicial/final 0. Las dieciséis reglas siguen a error. CheckJs=false conserva su límite real.
- Artefacto/CAS y consumidor autónomo: con el mismo flock pesado y Node por Nix, `node .cache/admision-completa-r36/artefacto.mjs` y `node .cache/admision-completa-r36/consumidor-sin-motor.mjs`. Este último bloquea imports del motor, TypeScript y productores R32/R35. Salidas en artefacto-final.log y consumidor-sin-motor-final.log. Solo escriben informes propios.

Todos los productores recibidos se importan o se adaptan a scratch; ninguno se ejecuta con salida en sus informes históricos. La adaptación de las 69 regresiones se entrega con diff. El schema inicial oneOf/allErrors se interrumpió con SIGTERM propio (salida 143), después se usa if/then para seleccionar operador: no se llama correcto al intento interrumpido. Los errores de preparación por un delimitador EOF residual ocurrieron tras escribir instrumentos propios y no son pruebas fiscales; las validaciones posteriores usan los archivos completos y sus bytes finales.

Los instrumentos .txt se copian a la ruta scratch indicada para repetirlos; son código de control, no fuentes fiscales. Las configuraciones conservan cacheDir propio. No hay Next build, servidor, preview ni suites Excel masivas. No se mantiene flock durante redacción, consultas o esperas.
