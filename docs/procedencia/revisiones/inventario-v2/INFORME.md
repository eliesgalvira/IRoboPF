# Contrarrevisión del inventario v2

**Conclusión: requiere cambios técnicos; no se certifica fiscalidad.** La CLI de reconstrucción supera los ataques del inventario anterior. Las identidades y la clasificación corrigen los casos originales. Quedan una aceptación incorrecta en la API con módulos previamente importados, una forma de objeto que el recorrido omite y un fallo de selección de fuentes dependiente del directorio del checkout. No se modifica la implementación.

Revisión personal sobre HEAD `12976509f7b78241e0da173e19557206f5d4330e`. `git diff 4a41ce0c --` para scripts de inventario, prueba, esquema, manifiesto, gzip, package.json y CI no muestra diferencias. Leídos BRIEF, AGENTS, INVENTARIO, CONTRATO-AUDITORIA, COORDINACION, DECISIONES, informe y findings anteriores; leídos los extractores TS/Python, grafo, lector/publicador, validador, esquema, pruebas y CI. No se mutó VCS, no se creó checkout ni se instaló dependencia de proyecto. node_modules es un enlace autorizado al compartido. Las ejecuciones usan copias propias dentro del scratch autorizado; el artefacto entregado permanece intacto.

## Los cuatro bloqueos previos

- **R01: cerrado para la CLI en proceso nuevo; abierto para la API reutilizada.** Valor adulterado, hoja con índice suprimidos, índice ausente, counts falsos, syntaxCoverage falso, ubicación imposible, grafo sustituido, archivo sobrante y evidencia accepted son rechazados por reconstrucción. Los hashes de páginas, índices y gzip se recalculan. `readArtifact` acepta los contenedores coherentes, como corresponde a su contrato: eso no es un fallo. `compareFiles` rechaza cada mutación frente al conjunto original previamente reconstruido. La CLI reconstruye en cada ataque. Pero `buildArtifact` usa imports cacheados en el proceso: véase INV2-R01 y su reproducción completa.
- **R02: cerrado para ocurrencias versionadas.** La inserción `[10,20]` → `[5,10,20]` no comparte IDs. El alias real MINIMOS_ESTATALES_2024 cambia de 5550 a 5551 al cambiar su dependencia de 2025, manteniendo el hash del archivo contenedor y renovando el ID. Las rutas son segmentos JSON. No se exige identidad jurídica permanente: la documentación la pospone correctamente. La caché de imports es un defecto de reconstrucción, no una colisión del hash del valor.
- **R03: casos originales corregidos, cierre general incompleto.** BigInt conserva 3; falso constructor Decimal conserva amount=123; toStringTag, ciclos, Date y Map se rechazan; aliases compartidos se expanden por ruta. Aun así, un objeto cuyo prototipo personalizado tiene prototipo null pasa y devuelve cero hojas pese a exponer amount=123. INV2-R03 solicita rechazarlo explícitamente. Además, NaN numérico y Decimal(NaN) llegan como texto y el filtro de hojas efectivas los descarta: observación acotada por inspección del filtro, sin afirmar NaN en el artefacto actual.
- **R04: cerrado dentro de la clasificación sintáctica declarada.** Math.floor/ceil son Rounding, surround es Formula, == y != son Condition, new Decimal es Formula y ?? es Condition. No se atribuye política monetaria a un nombre de función. Aliases, shadowing, llamadas por acceso computado y análisis interprocedimental siguen fuera de la garantía.

## Evidencia ejecutada y límites

La primera ejecución literal en scratch produjo 13/14: su ruta contiene `/procedencia/` y el filtro absoluto elimina todos los módulos. Se conserva el fallo en `tests.log`, sin atribuirlo al artefacto. Para seguir sin parchear generadores se usa un preload únicamente en los procesos Bun de revisión: `process.cwd = () => '/proc/self/cwd'`. Es un alias Linux del mismo directorio y evita el segmento problemático. La reconstrucción con ese alias coincide byte a byte con el artefacto original. Los intentos auxiliares fallidos se conservan; un `bun --preload ... run` que mostró ayuda no se cuenta como prueba. La ejecución final real utiliza `node node_modules/vitest/vitest.mjs run --config scripts/procedencia/inventario-vitest.mjs --maxWorkers=1 --no-cache`: **14/14**, 22,65 s. Los subprocess Bun heredan el wrapper con preload.

La reconstrucción baseline comprobó 98 fuentes TS, un Python, 19.967 ocurrencias sintácticas, 16.100 efectivas y 11.727 seleccionadas, 25.171 unidades pendientes y 351 fichas. Son **47.794 ocurrencias con solapamiento**, no parámetros fiscales distintos. Se mantienen 288 sondeos y ninguna aceptación fiscal. Los 341 archivos, el índice mínimo y gzip evitan la duplicación de índice anterior. El verificador compara el conjunto exacto y contenido de todos los auxiliares, no solo hashes.

`mutations.json` conserva por ataque la lectura del contenedor, comparación API y resultado CLI. Además se modificaron, por separado y restaurando después, fuente TS, bun.lock y generador: los tres fallaron por diferencias respecto a las fuentes. Se ensayaron duplicados y `../evil.json`: rechazo antes de extracción a disco. Un gzip de 128 MiB + 1 byte descomprimido se rechazó con límite 134217728. Un destino no vacío fue rechazado. La mezcla de blob nuevo y manifiesto anterior también fue rechazada. La exclusividad de `mkdtemp` y el orden de dos rename se comprobaron en código; no se simuló apagado físico, fsync ni concurrencia de publicadores. No se atribuye durabilidad transaccional.

Python **-O** valida las 47.794 ocurrencias originales mediante JSON Schema y reconstrucción. Se repite también sobre el valor adulterado con hashes coherentes; véase `api-python.log`. No hay asserts en el validador. La CI ejecuta reconstrucción y las 14 pruebas, pero no ejecuta el validador Python/schema: no debe describirse como cobertura de schema en CI. El schema restringe pending; la reconstrucción exacta cubre auxiliares aunque estos no tengan esquema propio.

Muestra externa al recorrido del extractor: **313 hojas** en Madrid 2025, Aragón 2024, simulada estatal 2026, Galicia 2014 a ambos lados de 17707,20 y Valencia 2022 antes/en el cambio de 28 de octubre. Se recorre runtime con una función independiente, sin llamar flatten; ninguna diferencia. Un visitante independiente de TypeScript compara **187 literales** por offset y expresión en auditoria-graficos y auditoria-excel, sin omisiones en esa muestra. Comparte parser TS, por lo que no es una segunda implementación de lenguaje. No se valida vigencia legal, todas las deducciones, todas las ramas ni todas las fechas.

La reconstrucción prueba correspondencia con un extractor concreto y el checkout, no exhaustividad de ese extractor. Puede repetir una omisión en ambas caras; el objeto de prototipo personalizado lo ilustra. Los exports indirectos se declaran como lagunas; las dimensiones se anuncian como inferencias por nombre/ruta. Esas limitaciones son honestas y no constituyen por sí solas bloqueos adicionales para esta entrega técnica. Python se analiza sin ejecutar el oracle. No se ha aceptado ningún hallazgo tributario.

## Lint y coste

Oxlint sobre los seis mjs de producción/prueba analizados: **16 reglas, un thread, cero diagnósticos, exit 0**. ESLint sobre los mismos archivos: exit 0. Se leyó la configuración: las quince reglas generales y la regla Effect están a error. El smoke de plugins en scratch no pudo probarse: oxlint excluye esos archivos incluso en los intentos con no-ignore; no se presenta como smoke aprobado. No se escribió Effect, ni se ejecutó typecheck como sustituto del análisis de mjs. No hubo build ni suite legacy.

`time -v` de la reconstrucción baseline: **8,90 s de pared y 2.321.700 KiB RSS máximo (~2,21 GiB)**, sin swap. No es el máximo de toda la revisión ni una garantía para CI; las pruebas completas mantienen padre e hijo y pueden consumir más. Se comprobó memoria antes de las tareas pesadas y se ejecutaron reconstrucciones serialmente. El gzip de unos 8,21 MB y ~68,2 MB JSON interno es asumible ahora; el parser y el TypeChecker amplifican sustancialmente la memoria. Mantener un worker y evitar varias reconstrucciones simultáneas en esta máquina. No se exige servicio ni infraestructura nueva.

## Reproducción y entrega

Los scripts de `evidencia/` deben copiarse a la raíz de una copia scratch con fuentes, scripts, tests, esquema, artefacto y dependencias compartidas. No se ejecutan desde la documentación ni contra fuentes de producción: `alias.mjs`, `cache-api.mjs` y `api-accept.mjs` modifican temporalmente una fuente y la restauran en finally; `python-corrupt.mjs` hace lo mismo con el artefacto de la copia.

Orden: baseline check; `review.mjs`; `sample.mjs`; `alias.mjs`; `cache-api.mjs`; `api-accept.mjs`; `limits.mjs`; validador Python -O original y `python-corrupt.mjs`. Si la ruta contiene `/procedencia/`, usar el preload citado y un wrapper Bun que lo aplique también a subprocess. `alias.mjs` crea el resultado fresco requerido por `cache-api.mjs`; este crea los archivos requeridos por `api-accept.mjs`. Las salidas JSON y logs acompañan al informe. Las reproducciones no son fixes ni archivos de aplicación.

Corregir INV2-R01, INV2-R02 e INV2-R03 y añadir regresiones antes de declarar cerrado el inventario técnico. La aceptación fiscal y el inventario semántico exhaustivo siguen siendo trabajos posteriores, independientemente de estos arreglos.
